# AI Coding Agents for AI and ML

AI coding agents can help you write code, explain error and also extend an experiment. How useful they are depends on when you use them, what context they can access, and which setup fits your work.

marimo lets you use AI inside the notebook editor. It also supports [`marimo pair`](https://docs.marimo.io/guides/generate_with_ai/marimo_pair/), which connects a coding agent to a running notebook. In this module, you will learn when to use each approach and why notebook context improves the result.

## 1. Build an analysis with AI

AI is useful when you can describe the result you want and check its work. In this section, you will use marimo's built-in AI features to create data, extend an analysis, and review each result.

Start with one small task and check the generated code before you keep it.

### Enable AI features

If you run marimo locally, use the built-in AI features in the editor. Then:

3. Open the **AI** tab and connect a hosted provider or a local Ollama model. Follow the [provider setup instructions](https://docs.marimo.io/guides/configuration/llm_providers/) for your choice.

### Ask AI to add a cell

The next two steps use the local marimo editor. They show how you can extend a notebook one cell at a time.


## 2. Give the assistant the context it needs

Open the Chat panel from the left sidebar. When you use marimo's built-in assistant, it can see your notebook code. You can also add the current value of a dataframe or control to a prompt. This helps when the task depends on what is in the notebook now.

### Add variables to a prompt

The example notebook contains a sales dataframe named `df`. It also contains controls named `metric_selector` and `segment_selector`. These variables hold the data and current choices used by the notebook.

Inside an AI prompt, type `@` followed by a variable name. For example, `@df` gives the assistant information about the current dataframe, including its columns, types, and values. Add `@metric_selector` and `@segment_selector` when the current choices are relevant.

Compare these two prompts:

```text
Create a chart that summarizes this data.
```

```text
Using @df, @metric_selector, and @segment_selector, add a cell that summarizes the selected metric for the selected segments and creates a bar chart.
```

The second prompt tells the assistant which current notebook values to use.

## 3. Work with a coding agent using marimo pair

Adding variables to a prompt works well for a focused task. For a larger task, an agent may need to inspect several cells, change code, run the notebook, and check the result. `marimo pair` gives a coding agent this access.

You can pair marimo with Codex, Claude Code, or OpenCode. The agent can read variables and cell outputs, test logic in a scratchpad, run cells, add or remove cells, and interact with UI elements. It works with the current notebook session instead of relying only on the saved Python file.

<Callout title="Why the running notebook helps">
The Python file contains the notebook source. The running notebook contains the latest values, outputs, and errors. `marimo pair` lets the agent use both while it works.
</Callout>

Install the marimo pair skill once:

```bash
npx skills add marimo-team/marimo-pair
```

Start a supported coding agent in the course repository. Enter this command in the agent:

```text
/marimo-pair pair with me on course/notebooks/module-4/4_1_ai_features_demo.py
```

Keep the notebook and terminal open while you work with the agent.

<Callout title="Using molab">
In molab, open the Actions panel and choose "Pair with an agent". Follow the instructions shown there to start a paired session.
</Callout>

### Start by asking the agent to inspect the notebook

Begin by asking the agent to inspect the notebook without changing it:

```text
Inspect the running notebook. Explain what df, metric_selector, segment_selector, and metric_summary contain. Do not edit the notebook yet.
```

Check that the answer matches the current notebook. This confirms that the connection is working and that the agent can see the variables you expect it to use.

Once you know that the connection works, give the agent one clear task:

```text
Add a section that finds rows with a margin below 0.4 for the segments currently selected in segment_selector. Show the result in a selectable table and add a bar chart of profit by region. Use the existing df and controls. Run the new cells and check that the notebook has no errors.
```

This task spans several cells. The agent must use the existing dataframe and control value. It must also add connected outputs and run the new cells. Because the agent is paired with the notebook, it can inspect the result and fix problems before it finishes.

<TryIt>
1. Ask the agent to inspect the notebook before it edits anything. Check its description against the visible values.
2. Ask it to add the low margin analysis. Watch which cells it creates and runs.
3. Change the selected segments. Confirm that the new table and chart update with the rest of the notebook.
</TryIt>

## 4. Review AI-generated work

You need to review code from built-in AI and from `marimo pair`. Check that the code answers the request and that the output agrees with the data.

For the low-margin analysis, check that the new cells use the existing `df` and `segment_selector`. Confirm that the table contains only rows below the requested margin and that the chart agrees with those rows.

Run marimo's notebook checker from the repository root:

```bash
uvx marimo check course/notebooks/module-4/4_1_ai_features_demo.py
```

Then inspect the file changes:

```bash
git diff -- course/notebooks/module-4/4_1_ai_features_demo.py
```

marimo notebooks are stored as Python files, so the diff shows the cells and code that the agent changed. Review these changes before keeping them.

<Callout title="Choose the right approach">
Use the built-in assistant for a focused task in one or two cells. Use `marimo pair` when a coding agent needs to inspect, change, and test a running notebook. You can use a hosted provider or a local Ollama model for the built-in assistant. See the [LLM provider guide](https://docs.marimo.io/guides/configuration/llm_providers/) for setup options.
</Callout>
