# AI Coding Agents for AI and ML

AI coding agents can help you write code, explain errors, and extend an experiment. How useful they are depends on when you use them, what context they can access, and which setup fits your work.

marimo lets you use AI inside the notebook editor. It also supports [`marimo pair`](https://docs.marimo.io/guides/generate_with_ai/marimo_pair/), which connects a coding agent to a running notebook. In this module, you will learn when to use each approach and why notebook context improves the result.

<Callout title="Dataset used in this module">
We will use a small synthetic sales dataset created for this course. Each row represents sales activity for a region, customer segment, and sales channel. The dataframe includes revenue, cost, customer satisfaction, and conversion status. The notebook also calculates profit and profit margin. The dataset is small so that you can focus on how the AI tools use notebook context.
</Callout>

## 1. When to let AI agents write code

AI assistance is useful when you can describe a clear task and check the result. For example, you can ask it to summarize a dataframe, add a chart, or refactor a repetitive cell. You still need to review the code and confirm that the output answers your question.

marimo provides several ways to use AI without leaving the editor:

- Use **Generate with AI** to add new cells from a prompt.
- Press `Ctrl/Cmd-Shift-E` to ask AI to change the current cell.
- Use inline completion while you write code.
- Run `marimo new "your prompt"` to generate a new notebook.

These features are a good fit for a focused task. See the [AI assistant guide](https://docs.marimo.io/guides/editor_features/ai_completion/) for setup instructions and the current list of supported providers.

<Callout title="Start with a task you can check">
Ask AI to produce a result that you can inspect. A successful cell run does not prove that the calculation or chart is correct.
</Callout>

## 2. Give AI agents the context they need

Your code is only part of the information an AI agent may need. In AI and ML work, the next step often depends on the current dataframe, model output, control value, or cell error. An assistant that is not connected to the running notebook cannot see this information unless you provide it.

### Add variables to a prompt

The example notebook contains a sales dataframe named `df`. It also contains controls named `metric_selector` and `segment_selector`. These variables hold the data and current choices used by the notebook.

Inside marimo, write `@` followed by a variable name to add that variable to an AI prompt. For example, `@df` gives the assistant information about the current dataframe, including its columns and data types. Add `@metric_selector` and `@segment_selector` when the current control values are relevant.

Compare these two prompts:

```text
Create a chart that summarizes this data.
```

```text
Using @df, @metric_selector, and @segment_selector, add a cell that summarizes the selected metric for the selected segments and creates a bar chart.
```

The second prompt tells the assistant which notebook values to use. The generated code can refer to the data and controls that are present in the running notebook.

### Connect an agent with marimo pair

Adding variables to a prompt works well for one request. A larger task may require an agent to inspect several cells, change code, run the notebook, and check the result. `marimo pair` is the recommended way to give a coding agent this access.

You can pair marimo with Codex, Claude Code, or OpenCode. The agent can read variables and cell outputs, test logic in a scratchpad, run cells, add or remove cells, and interact with UI elements. It works with the current notebook session instead of relying only on the saved Python file.

<Callout title="Why the running notebook helps">
The Python file contains the notebook source. The running notebook contains the latest values, outputs, and errors. `marimo pair` lets the agent use both while it works.
</Callout>

### Start by asking the agent to inspect the notebook

Begin by asking the agent to inspect the notebook without changing it:

```text
Inspect the running notebook. Explain what df, metric_selector, segment_selector, and metric_summary contain. Do not edit the notebook yet.
```

Check that the answer matches the current notebook. This confirms that the connection is working and that the agent can see the variables you expect it to use.

Once you know that the connection works, give the agent one clear task:

```text
Add a section that finds rows with a margin below 0.4 for the segments currently selected in segment_selector. Show the result in a selectable table and add a bar chart of profit by region. Use the existing df and controls. Run the new cells and check that the notebook has no errors.
```

This task spans several cells. The agent must use the existing dataframe and control value. It must also add connected outputs and run the new cells. Because the agent is paired with the notebook, it can inspect the result and fix problems before it finishes.

<TryIt>
1. Ask the agent to inspect the notebook before it edits anything. Check its description against the visible values.
2. Ask it to add the low margin analysis. Watch which cells it creates and runs.
3. Change the selected segments. Confirm that the new table and chart update with the rest of the notebook.
</TryIt>

### Review the result

Notebook access helps an agent test its changes, but you still need to review the result. Check that the new cells use the existing `df` and `segment_selector`. Confirm that the table contains only rows below the requested margin and that the chart agrees with those rows.

Run marimo's notebook checker from the repository root:

```bash
uvx marimo check course/notebooks/module-4/4_1_ai_features_demo.py
```

Then inspect the file changes:

```bash
git diff -- course/notebooks/module-4/4_1_ai_features_demo.py
```

marimo notebooks are stored as Python files, so the diff shows the cells and code that the agent changed. Review these changes before keeping them.

The agent can inspect the result as it works, but you still decide whether to keep the changes.

## 3. Choose the right AI agent setup

Choose a setup based on the task and the notebook context that the agent needs.

marimo supports hosted providers and local models through Ollama. You can choose separate models for chat, cell editing, and inline completion. For example, you can use one model for inline completion and another model for the Chat panel.

<Callout title="Hosted and local models">
This course does not require Ollama. See the [LLM provider guide](https://docs.marimo.io/guides/configuration/llm_providers/) for the current setup options.
</Callout>

Use the built in assistant for a focused task. Use `marimo pair` when the task depends on the running notebook or requires changes across several cells. In both cases, review the generated code and its output before keeping it.
