An interactive notebook is a great place to begin a project because it lets you experiment and test ideas quickly. However, your requirements may change when you need to share your work with others or integrate it into a larger production system.

In this module, you will learn how to share and reuse your marimo notebook, then create a custom view of its analysis with marimo-studio.

## 1. Share your notebook in multiple ways

### 1.1 Explore the occupancy notebook

Imagine you work for a company that wants to estimate whether a meeting room is occupied from its sensor readings. Your task is to compare the predicted occupancy with the recorded occupancy and choose a decision threshold. A false positive could keep the lights on in an empty room. A false negative could turn them off while people are still there.

We will use this example throughout the module.

Explore the occupancy notebook below. The sensor data is included, so you can run the example directly in the course.

The following marimo notebook contains 8,143 sensor readings and a slider for the decision threshold. A reading is predicted as occupied when its score is at least the threshold. These controls use the widgets introduced in [Module 3](/?module=3).

## 2. Use your notebook as a script or Python module

### 2.1 Run the notebook as a script

You can run the occupancy notebook you explored above as a script from the command line. This is useful when you want to run the same analysis repeatedly without opening the notebook interface. For example, you might want to process a batch of sensor readings and save the results for a dashboard or report.

As you saw in Module 1, a notebook cell can have a Python function name. Here, `script_options` is the cell that reads the input file, threshold, and output filename. The updated cells use these values when the notebook runs as a script.

<MarimoEmbed
  notebook="/notebooks/module-5/occupancy.py?v=20261005-1"
  title="Add script support to the occupancy notebook"
/>

In the notebook, the `script_options` cell reads three command-line arguments:

- `--input` specifies the sensor data file. If you leave it out, the notebook uses `public/occupancy.csv`.
- `--threshold` specifies the threshold to use.
- `--output` specifies where to save the predictions.

The `selected_model` cell uses the threshold from the command line when the file runs as a script. The `save_predictions` cell writes the CSV and prints the summary. In the editor, the notebook continues to use the slider.

To try it in a terminal, run the command below from the folder containing `occupancy.py` and the `public` data folder:

```bash
uv run occupancy.py \
  --threshold 0.5 \
  --output occupancy_predictions.csv
```

You should see output similar to the following:

```text
Wrote 8143 rows to occupancy_predictions.csv
False positives: 90; false negatives: 5
```

### 2.2 Reuse the evaluation in another notebook

Another advantage of a marimo notebook is that it is a Python file. You can import its functions into another notebook instead of copying code.

You already have an occupancy notebook in Section 1.1. Its `score_readings()` and `evaluate_occupancy()` functions are already in the correct format for reuse: each is defined in its own cell and uses imports from the setup cell. When your own function follows this pattern, marimo marks it as reusable in the editor.

## 3. Create views from one notebook with marimo Studio

App view and exports let you share a notebook as it is. Sometimes, however, different audiences need different ways to use the same analysis. Copying the notebook for each audience can create versions that drift apart. Adding all the presentation code to the notebook can also make the analysis harder to read.

With [marimo Studio](https://marimo.io/blog/introducing-marimo-studio), the analysis stays in one notebook while you create separate views on top of it.

<img src={studioNotebookViews} alt="Without Studio, separate notebook copies or presentation code inside one notebook serve each audience. With Studio, one notebook provides separate views for different audiences." />

<p className="figure-caption">
  marimo Studio keeps the analysis in one notebook and gives each audience a separate view. A change to the analysis can then be used by every view. Source: <a href="https://marimo.io/blog/introducing-marimo-studio">Introducing marimo-studio</a>.
</p>

For our occupancy analysis, the same notebook can be useful in three different ways:

- A **facilities team** might want a monitor showing the current occupancy results.
- Someone choosing the **decision threshold** might need a model review that makes false positives and false negatives easier to compare.
- A **manager** might want a short report summarising the results.

All three can use results from the same `occupancy.py` notebook. The notebook continues to contain the data and Python calculations. Each view chooses which results to show and how to arrange them.

Our notebook already calculates the selected threshold, precision and recall, false positive and false negative counts, and rows where the prediction was incorrect. A view can use these results instead of calculating them again.

### 3.1 Create a monitor

You can create and edit Studio views yourself or use a coding assistant. Studio works with marimo's built-in AI assistant as well as external coding agents.

In this section, we will use **marimo's AI assistant**, introduced in [Module 4](/?module=4), because it is available directly inside the notebook editor. The agent can inspect the notebook, create the view files, and connect them to existing notebook results.

The calculations will stay in `occupancy.py`; the view will control how those results are presented.

<Callout title="Start Studio and open marimo AI">

This activity runs locally. Open a terminal in the course folder that contains `occupancy.py`, then start marimo with Studio:

```bash
uvx --with marimo-studio marimo edit occupancy.py --sandbox --watch
```

Open the Studio preview for the notebook. Then open the AI sidebar in the notebook editor and switch it to **Code Mode**. If you prefer another coding assistant, you can use the same prompts there as long as it can access the notebook and Studio project files.

</Callout>

First, ask the agent to inspect the notebook:

```text
Inspect occupancy.py.

Identify the exact notebook cells and values that contain:
- the threshold control
- occupancy results
- precision and recall
- false positive and false negative counts
- prediction errors

List their names and briefly explain what each one contains.

Do not change any files yet.
```

AI agents word their answers differently each time, so your response will not match exactly. It should identify similar cells. In our run, the agent found that the notebook already contains everything the view needs:

- `threshold_control` contains the threshold slider.
- `selected_model` calculates the predictions, metrics, and error rows.
- `metrics_output` displays precision, recall, false positives, and false negatives.
- `errors_output` displays the rows where the prediction is incorrect.

The underlying calculations remain in `score_readings()` and `evaluate_occupancy()`.

We can now build a view from these existing notebook results instead of calculating them again.

Now create the first view:

```text
Create a plain HTML Studio view named monitor for occupancy.py.

The view is for a facilities team. Show:
- the current threshold using threshold_control
- precision and recall from model_summary
- false positive and false negative counts from model_summary
- a short occupancy summary based on the existing notebook results

Use the existing cells and values from occupancy.py. Keep all calculations,
including score_readings() and evaluate_occupancy(), in the notebook.
Do not recreate these calculations in the view.

Build the view and show it in Preview.
```

The agent chooses its own layout, so your monitor will look a little different. It should be similar to the one in the video below: the threshold slider, a short occupancy summary, and cards for precision, recall, false positives, and false negatives.

### 3.2 Create a model review

The monitor gives a quick overview. Someone choosing the decision threshold needs more detail about how that threshold affects errors. At `0.5`, the notebook produces 90 false positives and 5 false negatives. At `0.7`, it produces fewer false positives but many more false negatives. The model review makes this tradeoff easier to inspect before choosing a threshold.

```text
Create another Studio view named model-review for occupancy.py.

This view is for someone choosing the occupancy decision threshold. Include:
- the notebook's threshold control
- precision and recall
- false positive and false negative counts
- a chart showing how false positives, false negatives, precision, and
  recall change across thresholds, with the current threshold marked
- a confusion matrix for the current threshold
- a chart of score distributions for empty and occupied readings, with
  the current threshold marked
- a table of prediction errors

Explain false positives and false negatives in plain language.

Use the existing notebook results and keep all calculations in occupancy.py.
If a chart needs new results, add notebook cells that reuse
evaluate_occupancy(). Do not recreate the evaluation logic in the view.

Build the view and show it in Preview.
```

Your model review will look something similar to the one shown below. It'll have a threshold slider and metrics at the top, a trade-off chart across thresholds, a confusion matrix, a score distribution chart, and the table of prediction errors. The agent may also add a few notebook cells to calculate the chart data.

### 3.3 Create a report

Finally, create a view for someone who needs to read the results rather than interact with the analysis.

```text
Create a Studio view named report for occupancy.py.

Present the occupancy analysis as a short report for a manager. Include:
- a headline with the current threshold, how many readings it
  misclassifies, and the threshold with the fewest total errors
- a short description of the task and what false positives and false
  negatives mean for the rooms
- precision and recall
- false positive and false negative counts
- a table comparing nearby thresholds, with the current one highlighted
- the threshold trade-off chart
- a short note on the method and its limits

Use the existing calculations from occupancy.py. Do not copy calculated
values into the view. If the report needs new numbers or text built from
results, add notebook cells that reuse the existing results. Build the
view and show it in Preview.
```
