An interactive notebook is a great place to begin a project because it lets you experiment and test ideas quickly. However, your requirements may change when you need to share your work with others or integrate it into a larger production system.

In this module, you will learn how to share and reuse your marimo notebook, then create a custom view of its analysis with marimo-studio.

## 1. Share your notebook in multiple ways

### 1.1 Explore the occupancy notebook

Imagine you work for a company that wants to estimate whether a meeting room is occupied from its sensor readings. Your task is to compare the predicted occupancy with the recorded occupancy and choose a decision threshold. A false positive could keep the lights on in an empty room. A false negative could turn them off while people are still there.

We will use this example throughout the module.

Explore the occupancy notebook below. The sensor data is included, so you can run the example directly in the course.

The following marimo notebook contains 8,143 sensor readings and a slider for the decision threshold. A reading is predicted as occupied when its score is at least the threshold. These controls use the widgets introduced in [Module 3](/?module=3).

## 2. Use your notebook as a script or Python module

### 2.1 Run the notebook as a script

You can run the occupancy notebook you explored above as a script from the command line. This is useful when you want to run the same analysis repeatedly without opening the notebook interface. For example, you might want to process a batch of sensor readings and save the results for a dashboard or report.

As you saw in Module 1, a notebook cell can have a Python function name. Here, `script_options` is the cell that reads the input file, threshold, and output filename. The updated cells use these values when the notebook runs as a script.

<MarimoEmbed
  notebook="/notebooks/module-5/occupancy.py?v=20261005-1"
  title="Add script support to the occupancy notebook"
/>

In the notebook, the `script_options` cell reads three command-line arguments:

- `--input` specifies the sensor data file. If you leave it out, the notebook uses `public/occupancy.csv`.
- `--threshold` specifies the threshold to use.
- `--output` specifies where to save the predictions.

The `selected_model` cell uses the threshold from the command line when the file runs as a script. The `save_predictions` cell writes the CSV and prints the summary. In the editor, the notebook continues to use the slider.

To try it in a terminal, run the command below from the folder containing `occupancy.py` and the `public` data folder:

```bash
uv run occupancy.py \
  --threshold 0.5 \
  --output occupancy_predictions.csv
```

You should see output similar to the following:

```text
Wrote 8143 rows to occupancy_predictions.csv
False positives: 90; false negatives: 5
```

### 2.2 Reuse the evaluation in another notebook

Another advantage of a marimo notebook is that it is a Python file. You can import its functions into another notebook instead of copying code.

You already have an occupancy notebook in Section 1.1. Its `score_readings()` and `evaluate_occupancy()` functions are already in the correct format for reuse: each is defined in its own cell and uses imports from the setup cell. When your own function follows this pattern, marimo marks it as reusable in the editor.

## 3. Create a custom view with marimo Studio

### 3.1 What is Studio?

With [marimo-studio](https://marimo.io/blog/introducing-marimo-studio), you can create separate views connected to the same notebook. Studio keeps each view in its own folder. The Python analysis stays in the notebook, while each view has its own layout and wording. You can use a coding agent to build these views.

### 3.2 Explore the official occupancy model review

Open the official [occupancy model review](https://marimo-team.github.io/marimo-studio/examples/occupancy?view=model-review) and move its threshold control. Observe how the false positive and false negative counts change. The same source notebook also has a monitor and a PDF report. These views show how you can present the same analysis for different tasks.

Now you will create your own simpler model review view from the course's `occupancy.py`. The goal is to help someone compare the two kinds of error before choosing a threshold. The score and evaluation functions will remain in the notebook.

### 3.3 Create your own `model_review` view

Use the occupancy notebook from the previous sections with the coding agent workflow introduced in [Module 4](/?module=4). You will need `uv` and a coding agent that can run terminal commands. Give the agent this request:

```text
Run `uvx --with marimo-studio agent-plugins read marimo-studio`
and set up Studio for the existing occupancy.py in this course folder.
Use its bundled public/occupancy.csv data. Keep score_readings() and
evaluate_occupancy() in the notebook.

Create a plain HTML view named model_review for a facilities team
choosing an occupancy threshold. Include the notebook's threshold control,
precision and recall, false positive and false negative counts, and a table
of errors. Explain the two types of error in plain language.

Use the notebook's threshold_control cell and its model_summary and
error_rows values. Keep the calculations in Python and connect the view
to those results. Explain that this is a weighted sensor score, not a
trained model, and that its metrics are measured on these observations.

Build the view, show it in Preview, and give me the local URL. Check that
changing the threshold updates both the metrics and the error table.
```

This follows the [Studio coding agent workflow](https://marimo-team.github.io/marimo-studio/guide/coding-agents). Open the generated view and compare it with the notebook. Both should show the same error counts when the threshold is the same.

### 3.4 See how it connects to the notebook

Studio views can reference named notebook cells and values. In this example, the view uses `threshold_control`, `model_summary`, and `error_rows` from `occupancy.py`. The calculations stay in Python, while the view decides how to arrange and present them.

Locate these three names in the generated view, then find the corresponding cell or value in `occupancy.py`. Ask the agent to help you trace the connection if needed.
