# Why Interactivity Accelerates AI Discovery

We touched on interactivity in Module 1. It deserves a closer look because it changes how you develop and understand AI systems.

In an interactive workflow, your data, model controls, and results stay connected. You can change an input, inspect the result, and decide what to try next. marimo runs the cells that depend on your change, so you do not need to run each step by hand.

## Data

You will work through one complete AI workflow using the [Adult Income dataset](https://archive.ics.uci.edu/dataset/2/adult). The dataset comes from US Census data. The task is to predict whether a person earns more than $50K per year.

This is a binary classification problem. The dataset contains numbers such as age and hours worked per week. It also contains categories such as occupation, education, and marital status.

Here is the path you will take:

1. Look at the raw data and edit a small sample.
2. Explore the data with charts and table transformations.
3. Choose the features and sample size used for modeling.
4. Fit TabICL and Random Forest, then compare their results.
5. Change the classification threshold and inspect model errors.

<Callout title="About the Adult Income dataset">
The UCI Machine Learning Repository provides this dataset. It was extracted from the 1994 Census database and contains 48,842 records. The input includes age, education, occupation, workclass, marital status, and hours worked per week. The model predicts one of two income groups: at or below $50K, or above $50K.
</Callout>

<Callout title="Error types">
A false positive is a person predicted to earn above $50K whose true label is at or below $50K.

A false negative is a person predicted to earn at or below $50K whose true label is above $50K.
</Callout>

The threshold controls the balance between these errors. Raising the threshold usually reduces false positives and increases false negatives. The best threshold depends on which error has a larger cost for the problem you are solving.

Select a few errors in the table and compare their features. This takes you from an overall score back to the data behind the score. You can use what you find to choose the next feature, sample, or threshold to test.

<TryIt>
Compare both models at a threshold of `0.5`. Then raise the threshold to `0.7`. Record how the false positive and false negative counts change. Select two errors and decide what you would try next.
</TryIt>
