# Why Interactivity Accelerates AI Discovery

Interactivity changes how you develop and understand AI systems. Imagine your data, models, visualisations and user input working together in a single system that updates automatically. You can seamlessly move from a question to an experiment to an answer without having to leave the system. This not only saves you time, but also helps you understand the effect of each change instantly.

marimo supports this kind of interactive computation by connecting the parts of a notebook that work together and in this section, you will see how it works in practice. You'll explore a dataset, select features, train models, and debug errors interactively in a single workflow. You will see how interactivity helps you understand the data, models, and results more quickly than a traditional notebook workflow.

Throughout this module, you will use marimo's [interactive UI elements](https://docs.marimo.io/api/inputs/). These are controls such as radio buttons and sliders. Each control has a current value that other cells can use. When you change the value, marimo updates the cells that depend on it. We will use the word "control" for these UI elements throughout the lesson.

### Data

You will work through an end-to-end AI workflow using the [Adult Income dataset](https://archive.ics.uci.edu/dataset/2/adult). The dataset comes from US Census data where the task is to predict whether a person earns more than $50K per year based on their demographic information. 

Here is the path you will take:

2. Explore the data visually.

## 3. Train and evaluate models

Once you have explored the data, the next step is to train models. In this section, you will train a [Decision Tree](https://scikit-learn.org/1.8/modules/generated/sklearn.tree.DecisionTreeClassifier.html) and a [Random Forest](https://scikit-learn.org/1.8/modules/generated/sklearn.ensemble.RandomForestClassifier.html) on the Adult Income data. Additionally, you will evaluate their performance to see how well they separate the two income classes. This comparison will help you decide which model to investigate further.

<div className="widget-label">Choose the features</div>

Different features provide different information to a model. Testing several feature combinations helps you see how a column affect the results. It can also reveal features that add little useful information. marimo provides a [multiselect control](https://docs.marimo.io/api/inputs/multiselect/) for this choice. You can simply add or remove features just by selecting them without editing any model code. 

When the selection changes, marimo prepares the feature table again, retrains both models, and updates their scores and probability plots.

<img
  src={modelInputControlsGif}
  alt="The feature selector and sample size slider update the data prepared for model training."
/>

<p className="figure-caption">Change a model input and marimo prepares the training and test data again.</p>

<div className="widget-label">Change the sample size</div>

The amount of training data can affect model performance and training time. Testing several sample sizes helps you see whether the results remain similar as more data is added.

We can use a marimo slider again for this choice. Moving the slider changes the number of rows in the training sample being fed to the models and thanks to reactivity, the choice is then propagated throughout the notebook. 

<img
  src={sampleSizeSliderGif}
  alt="The sample size slider changes the number of rows in the sampled dataframe."
/>

<p className="figure-caption">Move the slider and check that the sampled dataframe contains the selected number of rows.</p>

<div className="widget-label">One connected experiment</div>

The feature selector and sample size slider affect the same prepared dataset which is then passed on to the models. marimo tracks these dependencies, so changing either control reruns the data preparation and model cells while leaving unrelated cells unchanged.

## 4. Debug errors interactively

A model score gives you an overall measure of performance, but it does not show which rows the model misclassified. In the final notebook, you will choose one of the two models and explore its errors interactively.

<div className="widget-label">Choose what to inspect</div>

Here, we use marimo UI elements again to control the analysis. The model selector is a [`mo.ui.radio()`](https://docs.marimo.io/api/inputs/radio/) control that lets you choose one model. The error type control uses another radio group to show all errors, false positives, or false negatives. The [`mo.ui.slider()`](https://docs.marimo.io/api/inputs/slider/) control sets the classification threshold that converts predicted probabilities into class predictions.
