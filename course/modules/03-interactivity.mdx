# Why Interactivity Accelerates AI Discovery

We touched on interactivity in the module 1, but it deserves its own module because it changes how you develop and understand AI systems.

Imagine your data, models, visualisations, and user input working together in a single system that updates automatically. You can move from a question to an experiment, inspect the result, and then decide what to try next.

marimo supports this kind of interactive computation by connecting the parts of a notebook that work together. This pattern is valuable in modern AI and ML workflows because it speeds up experimentation and helps you understand the effect of each change.

In this module, we will see how interactivity brings data, model inputs, visualisations, and results together in one model-development workflow.

### Data

You will work through one complete AI workflow using the [Adult Income dataset](https://archive.ics.uci.edu/dataset/2/adult). The dataset comes from US Census data. The task is to predict whether a person earns more than $50K per year. This is a binary classification problem. The dataset contains numbers such as age and hours worked per week. It also contains categories such as occupation, education, and marital status.

Here is the path you will take:

1. Look at the raw data and edit a small sample.
2. Explore the data with charts and table transformations.
3. Choose the features and sample size used for modeling.
4. Fit TabICL and Random Forest models, then compare their results.
5. Change the classification threshold and inspect model errors.

<Callout title="Error types">
A false positive is a person predicted to earn above $50K whose true label is at or below $50K.

A false negative is a person predicted to earn at or below $50K whose true label is above $50K.
</Callout>

The threshold controls the balance between these errors. Raising the threshold usually reduces false positives and increases false negatives. The best threshold depends on which error has a larger cost for the problem you are solving.

Select a few errors in the table and compare their features. This takes you from an overall score back to the data behind the score. You can use what you find to choose the next feature, sample, or threshold to test.
