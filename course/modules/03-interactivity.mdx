# Why Interactivity Accelerates AI Discovery

We touched on interactivity in the module 1, but it deserves its own module because it changes how you develop and understand AI systems.

Imagine your data, models, visualisations, and user input working together in a single system that updates automatically. You can move from a question to an experiment, inspect the result, and then decide what to try next.

marimo supports this kind of interactive computation by connecting the parts of a notebook that work together. This pattern is valuable in modern AI and ML workflows because it speeds up experimentation and helps you understand the effect of each change.

In this module, we will see how interactivity brings data, model inputs, visualisations, and results together in one model-development workflow.

### Data

You will work through one complete AI workflow using the [Adult Income dataset](https://archive.ics.uci.edu/dataset/2/adult). The dataset comes from US Census data. The task is to predict whether a person earns more than $50K per year. This is a binary classification problem. The dataset contains numbers such as age and hours worked per week. It also contains categories such as occupation, education, and marital status.

Here is the path you will take:

1. Inspect and edit the data.
2. Explore the data visually.
3. Fit and compare two models.
4. Debug model errors interactively.

Each section includes an embedded marimo notebook. First, explore the notebook and try its controls for yourself. Then complete the questions in the "Try it" block. You can open any notebook in a new tab by clicking the link in its top right corner.

## 3. Train and evaluate models

Once you have explored the data, the next step is to train models. You will train a [Decision Tree](https://scikit-learn.org/1.8/modules/generated/sklearn.tree.DecisionTreeClassifier.html) and a [Random Forest](https://scikit-learn.org/1.8/modules/generated/sklearn.ensemble.RandomForestClassifier.html) on the Adult Income data. Both models use the same selected rows, features, and train and test split.

You will evaluate their scores and predicted probabilities to understand how they behave. This comparison will help you decide which model to investigate further.

<div className="widget-label">Choose the features</div>

Different features provide different information to a model. Testing several feature combinations helps you see which columns affect the results. It can also reveal features that add little useful information. marimo provides a [multiselect control](https://docs.marimo.io/api/inputs/multiselect/) for this choice. You can add or remove features without editing the model code. The selected columns are used to prepare one feature table for both models.

When the selection changes, marimo prepares the feature table again, retrains both models, and updates their scores and probability plots.

<Callout title="Video placeholder">
A short video will show one feature being removed and both model scores updating.
</Callout>

<div className="widget-label">Change the sample size</div>

The amount of training data can affect model performance and training time. Testing several sample sizes helps you see whether the results remain similar as more data is added.

marimo provides a slider for changing the sample size. Both models receive the same selected rows, so the comparison remains fair. When the slider changes, marimo creates a new training sample, retrains both models, and updates the evaluation results.

The slider is included to help you study the effect of training data size. In a real project, you would usually use all available training data unless there is a reason not to.

<Callout title="Video placeholder">
A short video will show the sample size changing and the model results updating.
</Callout>

<div className="widget-label">One connected experiment</div>

The feature selection and sample size controls both affect the same prepared dataset which is then passed to the Decision Tree and Random Forest. marimo tracks these dependencies, so changing either control reruns the data preparation and model cells while leaving unrelated cells unchanged.

## 4. Debug errors interactively

A model score gives you an overall measure of performance, but it does not show which rows the model misclassified. In the final notebook, you will choose one of the two models and explore its errors interactively.

<div className="widget-label">Choose what to inspect</div>

The model selector chooses which model to analyse. The threshold slider converts predicted probabilities into class predictions. The error type control lets you view all errors, false positives, or false negatives.
