An interactive notebook is a great place to begin an AI or ML project because it lets you experiment and test ideas quickly. However, your requirements may change when you need to share your work or integrate it into a larger production system.

marimo lets you move from a notebook to a script, web app, shareable artifact, or reusable Python module without rewriting your code and in this module, you will see exactly how to do this.

## 1. Start with a notebook

Imagine you work for a company that wants to understand sentiment in customer feedback. In this exercise, you will use two open-weight LLMs to classify twelve product reviews as positive, negative, or neutral using zero-shot classification. You will then compare how the models label the same reviews.

<img src={sentimentClassifierFlow} alt="Twelve product reviews go through a zero-shot prompt to two Ollama models. Each model returns sentiment labels, and the results are compared." />

### Set up Ollama

This time you will work with local, open-weight models through Ollama: `gemma3:1b` and `qwen3:1.7b`. These small models download quickly and can run on most local machines. This notebook sends requests directly to your local Ollama server, so you do not need to configure marimo's editor AI provider.

<details className="setup-details">
  <summary>Set up Ollama and download the models</summary>

  1. Download and install [Ollama](https://ollama.com/download).
  2. From the command line, start the local server:

  ```bash
  ollama serve
  ```

  3. From a second command line window, download the two models for this module:

  ```bash
  ollama pull gemma3:1b
  ollama pull qwen3:1.7b
  ```


</details>

### Run the starter notebook

The notebook below is the starting point for this module. It contains twelve product reviews, two controls for choosing models, and a button to run the comparison. These controls are widgets, like the ones you used in [Module 3](/?module=3). When you select **Classify with both models**, marimo sends every review to each model. Each model returns a sentiment label, confidence score, and short reason. The results appear in a dataframe, with one row for every review and model pair.

## 2. Turn the notebook into a web app

Sometimes, you only want to interact with a notebook without seeing its code. App view makes this possible. It is useful when sharing the end result with business stakeholders or others who do not need to edit the analysis.

To view your notebook in the app view, select the **preview** button in the bottom right of the marimo editor. This opens the notebook with its code hidden, leaving only the controls and results visible. 

<ImagePlaceholder
  title="Web app GIF"
  description="Show the app preview button in the marimo editor, then the sentiment classifier with its code hidden and its controls and results visible."
/>

Or, you can also start the notebook in app mode from the command line:

```bash
marimo run notebook.py
```


Replace `notebook.py` with the name of your marimo notebook. The `marimo run` command turns the notebook into an app and starts a local web server for it. Open the address printed in the command line to use the app.

By default, marimo places the notebook outputs one after another and hides the code. You can arrange the outputs with the drag-and-drop grid editor, or choose to show code in the app view.


## 3. Run the notebook as a script
Imagine that the company receives a new batch of product reviews every day. For this sentiment-classification example, the script takes that batch, asks both models for labels, and saves the results to a CSV file for a dashboard or weekly report. You do not need to open the notebook or select its button.

The classifier is already in the starter notebook. To run this daily batch without the interface, paste the block below at the bottom of the file. Replace the existing final `if __name__` block with this one.

```python
@app.function
def run_headless(argv):
    import argparse

    parser = argparse.ArgumentParser()
    parser.add_argument("--model-a", default="gemma3:1b")
    parser.add_argument("--model-b", default="qwen3:1.7b")
    parser.add_argument("--output", default="results.csv")
    args = parser.parse_args(argv)

    results = compare_reviews(REVIEWS, args.model_a, args.model_b)
    results.to_csv(args.output, index=False)
    print(f"Wrote {len(results)} rows to {args.output}")

if __name__ == "__main__":
    import sys

    if len(sys.argv) > 1:
        run_headless(sys.argv[1:])
    else:
        app.run()
```

Now run this command from the folder that contains your notebook. `uv run` prepares the packages listed at the top of the notebook, then runs the file.

```bash
uv run 0_sentiment_classifier_starter.py \
  --model-a gemma3:1b \
  --model-b qwen3:1.7b \
  --output results.csv
```

The command uses the two default models and writes the result to `results.csv`. The file has 24 rows: one result for each review and model combination.

In this example, `--model-a` and `--model-b` choose the two models to compare, while `--output` chooses the name of the CSV file.

## 4. Export and share a report

The script creates a CSV file. This report notebook reads that file and gives you a simple view that you can export or share.

Export the report when you need a file that someone else can open:

```bash
marimo export html 3_sentiment_classifier_report.py -o report.html
marimo export pdf 3_sentiment_classifier_report.py -o report.pdf
marimo export html-wasm 3_sentiment_classifier_report.py -o wasm_output --mode run
```

Use HTML for a report that someone can open in a browser, PDF for a fixed document, and WASM when you want a browser-based interactive version.

## 5. Reuse the classifier in another notebook

The comparison logic can also become a Python module. `classifier_module.py` exposes `get_client()` and `compare_two_models()` with `@app.function`, so another notebook can import them.

The evaluation pipeline uses the same functions with a new set of reviews. It does not copy the Ollama connection or comparison code.

```python
from classifier_module import compare_two_models, get_client

client = get_client()
results = compare_two_models(client, texts, model_a="gemma3:1b", model_b="qwen3:1.7b")
```
