An interactive notebook is a great place to begin an AI project because it lets you experiment and test ideas quickly. However, your requirements may change when you need to share your work or integrate it into a larger production system.

marimo lets you move from a notebook to a script, web app, shareable artifact, or reusable Python module without rewriting your code and in this module, you will see exactly how to do this.

## 1. Build a sentiment classifier

Imagine you work for a company that wants to understand sentiment in customer feedback. In this exercise, you will use two open-weight LLMs to classify twelve product reviews as positive, negative, or neutral using zero-shot classification. You will then compare how the models label the same reviews.

<img src={sentimentClassifierFlow} alt="Twelve product reviews go through one zero shot prompt to two Ollama models. Each model returns sentiment labels, and the results are compared." />

### Set up Ollama

This module uses `gemma3:1b` and `qwen3:1.7b` through Ollama. Both models run on your computer, so you do not need an API key. You also do not need to connect Ollama to marimo's editor AI settings because the notebook sends requests directly to the local Ollama server.

<details className="setup-details">
  <summary>Install Ollama and download the models</summary>

  1. Download and install [Ollama](https://ollama.com/download).
  2. Start the local server from the command line.

  ```bash
  ollama serve
  ```

  3. Open a second command line window and download the models.

  ```bash
  ollama pull gemma3:1b
  ollama pull qwen3:1.7b
  ```

</details>

### Run the classifier

The embedded notebook contains the twelve reviews, two fields for the model names, and a button that starts the comparison. These controls use the widgets introduced in [Module 3](/?module=3).

When you select **Classify with both models**, the notebook sends each review to both models. Each response contains a sentiment label, a confidence score, and a short reason. The final dataframe places both answers beside the original review so you can compare them.

<Callout title="Before you run">
Start Ollama and download both models before selecting **Classify with both models**. The comparison can take some time because the notebook makes 24 model requests.

## 2. Share the notebook as a web app

Sometimes, you only want to interact with a notebook without seeing its code. App view makes this possible. It is useful when sharing the end result with business stakeholders or others who do not need to edit the analysis.

In the marimo editor, select the **preview** button in the bottom right corner. App view hides the code and shows the controls and results. You can use the grid editor if you want to arrange the outputs before sharing the app.

<ImagePlaceholder
  title="Open the classifier in app view"
  description="Show the preview button in the marimo editor, followed by the classifier with its code hidden and its controls visible."
/>

You can also start app view from the command line. Run this command from the folder that contains the notebook:

```bash
marimo run sentiment_classifier.py
```

marimo starts a local web server and prints an address. Open that address in a browser to use the app. The server must keep running while other people use it.

## 3. Run the notebook as a script

Script mode is useful when you need to run the classifier repeatedly, such as processing a daily batch of product reviews and saving the results for a dashboard or report.

This notebook already contains the classification logic. The only change is how it receives its inputs. Instead of taking model names from notebook controls, the script receives them as command-line arguments and writes the results to a CSV file.

To support script mode, the notebook uses a helper named `run_as_script()`. It reads three values from the command line:

- `--model-a` chooses the first model.
- `--model-b` chooses the second model.
- `--output` sets the name of the CSV file.

It then calls the same `compare_reviews()` function used by the notebook controls and saves the dataframe.

<img src={sentimentClassifierScriptFlow} alt="Model names and an output filename are passed to the classifier, which saves the results as a CSV file." />

Enter this command in the command line from the folder that contains `sentiment_classifier.py`:

```bash
uv run sentiment_classifier.py -- \
  --model-a gemma3:1b \
  --model-b qwen3:1.7b \
  --output results.csv
```

The `--` separates the notebook filename from the arguments for the classifier. The command creates 24 rows because both models classify all twelve reviews.

## 4. Export and share the notebook

When you share a notebook directly, interactive controls and plots may not work for the recipient. marimo provides several export options that preserve the notebook's results in a format that is easier to share, including static HTML, PDF, and interactive WebAssembly HTML. Each format has different advantages so you can choose an export format based on how someone will use the report:

- Static HTML opens in a browser and shows the outputs that were present when you exported it.
- PDF gives you a fixed document.
- WASM HTML runs the notebook in the browser, so supported controls remain interactive without a Python server.

After you run the classifier in the editor, open the notebook menu and select **Download as static HTML** to save the current view.

<ImagePlaceholder
  title="Export the current notebook view"
  description="Show the completed classifier results, the notebook menu, and the Download as static HTML option."
/>

You can also export from the command line. Enter these commands from the folder that contains the notebook:

```bash
marimo export html sentiment_classifier.py -o sentiment_report.html
marimo export pdf sentiment_classifier.py -o sentiment_report.pdf
marimo export html-wasm sentiment_classifier.py -o sentiment_wasm --mode run
```

<Callout title="WASM and local models">
A WASM notebook runs in the browser, but this classifier still needs access to Ollama. Someone without Ollama cannot send new reviews to the local models. Use static HTML or PDF when you only need to share completed results.
</Callout>

## 5. Reuse the classifier in another notebook

Since a marimo notebook is a Python file, many of the standard Python features can be used with it. For example, you can import functions from one marimo notebook into another. This lets you reuse notebook code without copying it.

For instance, we can use the classifier function created in the previous notebook in a second notebook that evaluates new reviews.

The sentiment classifier defines `compare_reviews()` with `@app.function`. A reusable function must be in its own cell. It can use imports and values from the setup cell, as well as other reusable functions.

The embedded notebook below imports `compare_reviews()` from the sentiment classifier and applies it to three new reviews.
