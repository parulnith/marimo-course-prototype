An interactive notebook is a useful place to begin an AI or ML project because it lets you experiment and test ideas quickly. However, the requirements may differ when you need to share your work with others or integrate it into a larger system. This module shows how to turn one notebook into a script, a web app, a shareable artifact, and a reusable Python module. 


## 1. Run a marimo notebook as a script

Suppose you have a set of product reviews and need to classify their sentiment. You want to compare two models to see which one gives the more accurate labels. The sentiment classifier sends each review to both models and records a sentiment label, confidence score, and explanation for each answer.

The classifier begins as a marimo notebook because you can inspect the answers before you use the evaluation in another setting. You will work directly in the embedded notebook, then run the same notebook as a script and save its results to a CSV file.

<Callout title="The reviews and models">

- The notebook includes twelve product reviews. They include clear opinions, sarcasm, and mixed experiences, so you can see where a simple sentiment label may be difficult.
- It has fields for two model names, a text area where each line is one review, and a **Classify with both models** button.
- It shows the models' answers side by side. You can mark each answer as correct or incorrect, then compare the accuracy scores and charts.

</Callout>

Before you run the embedded notebook, start Ollama and download the two default models:

```bash
ollama serve
ollama pull gemma3:1b
ollama pull qwen2.5:0.5b
```

### Classify the reviews

Work in the embedded notebook above. You do not need to open a separate notebook.

1. Keep the default model names, or replace one with a model that is available in your local Ollama server.
2. Read the reviews in the text area. Add or replace a review if there is a case that you want to test.
3. Select **Classify with both models** and inspect the two answers for each review.
4. Mark the classifications that you think are correct. The accuracy dashboard and charts update from your choices.

<Callout title="The evaluation data">

The results dataframe has one row for every review and model combination. It contains the review text, model name, sentiment label, confidence score, and a short explanation. The script will save this same data to a CSV file.

</Callout>

### Run the notebook from the terminal

Once you have inspected the results in the notebook, you can run the same file as a standard Python script from the terminal. Near the end of `sentiment_classifier.py`, `run_headless()` reads command-line arguments and calls the same `compare_two_models()` function that the notebook uses. This repeats the evaluation without requiring you to use the notebook interface.

```python
@app.function
def run_headless(argv):
    # Read CLI arguments, run both models, and optionally write a CSV.
    ...
```

The file checks for arguments after `--`. If it finds them, it runs the command-line workflow. Otherwise, it opens as a normal marimo notebook.

Run the evaluation and write its results to a CSV file:

```bash
uv run python sentiment_classifier.py -- \
  --model-a gemma3:1b \
  --model-b qwen2.5:0.5b \
  --output results.csv
```

Open `results.csv`. Each review should have one row for each model. The output includes `text`, `model`, `label`, `confidence`, and `reason`.

## 2. Publish the notebook as a web app

The classifier already has the controls needed for an app. Run the same file in app mode:

```bash
marimo run sentiment_classifier.py
```

People using the app can choose models, add reviews, run the evaluation, and inspect the results. They do not need to work in code cells.

The controls are Python objects created with `mo.ui`. Their current values are available through `.value`.

```python
model_a_input = mo.ui.text(value=args.model_a, label="Model A")
reviews_input = mo.ui.text_area(label="Reviews to classify")
run_btn = mo.ui.run_button(label="Classify with both models")

results_df = compare_two_models(
    client,
    reviews_input.value.splitlines(),
    model_a_input.value,
    model_b_input.value,
)
```

You used controls in Module 3. Here, the same controls let someone use your work as an app. marimo updates the results table and accuracy dashboard when a person runs a new evaluation.

<Callout title="Share on your network">
To make the app available on your local network, run `marimo run sentiment_classifier.py --host 0.0.0.0 --port 8080`.
</Callout>

## 3. Export and share your work

An app is useful when people can open it. An export is useful when people need a file they can keep or publish.

Start with an HTML report:

```bash
marimo export html sentiment_classifier.py -o report.html
```

Open `report.html` in a browser. It is a portable snapshot of the notebook output that you can attach to documentation or share with a teammate.

You can also export a PDF for a fixed report:

```bash
marimo export pdf sentiment_classifier.py -o report.pdf
```

For a browser-based interactive export, use WASM:

```bash
marimo export html-wasm sentiment_classifier.py -o wasm_output --mode run
```

You can share the notebook source through GitHub or molab when you want someone to inspect the code or make changes themselves.

3. Choose either PDF or WASM for a second export.
4. Decide which format you would send to a teammate who only needs the results.
</TryIt>

## 4. Import notebook functions into another notebook

The classifier also works as a Python module. Its reusable functions use `@app.function`, which makes them available to another Python file.

```python
@app.function
def get_client(base_url="http://localhost:11434/v1", api_key="ollama"):
    return OpenAI(base_url=base_url, api_key=api_key)


@app.function
def compare_two_models(client, texts, model_a, model_b):
    ...
```

The imports, constants, and shared configuration live in `app.setup` near the top of the classifier. This gives the reusable functions access to the code they need when another file imports them.

Open the pipeline notebook:

```bash
marimo edit eval_pipeline.py
```

It imports and uses the functions from the classifier:

```python
from sentiment_classifier import compare_two_models, get_client

client = get_client()
results = compare_two_models(
    client,
    texts,
    model_a="gemma3:1b",
    model_b="qwen2.5:0.5b",
)
```
