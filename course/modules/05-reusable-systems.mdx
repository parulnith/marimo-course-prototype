You can use the same marimo notebook in several ways. In this module, you will use a small LLM evaluation harness as a notebook, a script, a web app, a published artifact, and a Python module.

The notebook compares two local Ollama models on product reviews. It keeps the model output in a dataframe, so you can inspect results in the notebook and reuse the same workflow elsewhere.

| Mode | Command |
| --- | --- |
| Notebook | `marimo edit sentiment_classifier.py` |
| Web app | `marimo run sentiment_classifier.py` |
| Script | `uv run python sentiment_classifier.py -- --model-a gemma3:1b --model-b qwen2.5:0.5b --output results.csv` |
| Python module | `from sentiment_classifier import get_client` |

## 1. Run interactive work as a script

Start with the classifier notebook. From `course/notebooks/module-5`, run:

```bash
marimo edit sentiment_classifier.py
```

The notebook sends each product review to two local Ollama models. It shows the label, confidence, and reason from each model. You can mark a classification as correct or incorrect and compare the models in the accuracy dashboard.

Before opening the notebook, start Ollama and download the default models:

```bash
ollama serve
ollama pull gemma3:1b
ollama pull qwen2.5:0.5b
```

The notebook has model inputs, a text area for reviews, a button that runs both models, and a results dataframe. This is an evaluation workflow. You can inspect the answers, compare the models, and keep the output for later work.

### Use the same workflow from the terminal

Near the end of `sentiment_classifier.py`, `run_headless()` reads command-line arguments and calls the same `compare_two_models()` function used by the notebook.

```python
@app.function
def run_headless(argv):
    # Read CLI arguments, run both models, and optionally write a CSV.
    ...
```

The file checks for arguments after `--`. If it finds them, it runs the command-line workflow. Otherwise, it opens as a normal marimo notebook.

Run the evaluation and write its results to a CSV file:

```bash
uv run python sentiment_classifier.py -- \
  --model-a gemma3:1b \
  --model-b qwen2.5:0.5b \
  --output results.csv
```

Open `results.csv`. Each review should have one row for each model. The output includes `text`, `model`, `label`, `confidence`, and `reason`.

## 2. Publish the notebook as a web app

The classifier already has the controls needed for an app. Run the same file in app mode:

```bash
marimo run sentiment_classifier.py
```

People using the app can choose models, add reviews, run the evaluation, and inspect the results. They do not need to work in code cells.

The controls are Python objects created with `mo.ui`. Their current values are available through `.value`.

```python
model_a_input = mo.ui.text(value=args.model_a, label="Model A")
reviews_input = mo.ui.text_area(label="Reviews to classify")
run_btn = mo.ui.run_button(label="Classify with both models")

results_df = compare_two_models(
    client,
    reviews_input.value.splitlines(),
    model_a_input.value,
    model_b_input.value,
)
```

You used controls in Module 3. Here, the same controls let someone use your work as an app. marimo updates the results table and accuracy dashboard when a person runs a new evaluation.

</Callout>

## 3. Export and share your work

An app is useful when people can open it. An export is useful when people need a file they can keep or publish.

Start with an HTML report:

```bash
marimo export html sentiment_classifier.py -o report.html
```

Open `report.html` in a browser. It is a portable snapshot of the notebook output that you can attach to documentation or share with a teammate.

You can also export a PDF for a fixed report:

```bash
marimo export pdf sentiment_classifier.py -o report.pdf
```

For a browser-based interactive export, use WASM:

```bash
marimo export html-wasm sentiment_classifier.py -o wasm_output --mode run
```

You can share the notebook source through GitHub or molab when you want someone to inspect the code or make changes themselves.

</TryIt>

## 4. Import notebook functions into another notebook

The classifier also works as a Python module. Its reusable functions use `@app.function`, which makes them available to another Python file.

```python
@app.function
def get_client(base_url="http://localhost:11434/v1", api_key="ollama"):
    return OpenAI(base_url=base_url, api_key=api_key)


@app.function
def compare_two_models(client, texts, model_a, model_b):
    ...
```

The imports, constants, and shared configuration live in `app.setup` near the top of the classifier. This gives the reusable functions access to the code they need when another file imports them.

Open the pipeline notebook:

```bash
marimo edit eval_pipeline.py
```

It imports and uses the functions from the classifier:

```python
from sentiment_classifier import compare_two_models, get_client

client = get_client()
results = compare_two_models(
    client,
    texts,
    model_a="gemma3:1b",
    model_b="qwen2.5:0.5b",
)
```

The pipeline does not copy the model connection or comparison logic. It imports the same functions that the classifier uses. When you improve the comparison function, both notebooks use the update.
