An interactive notebook is a great place to begin a project because it lets you experiment and test ideas quickly. However, your requirements may change when you need to share your work with others or integrate it into a larger production system.

In this module, you will learn how to share and reuse your marimo notebook, then create a custom view of its analysis with marimo-studio.

## 1. Share your notebook in multiple ways

### Explore the occupancy notebook

Imagine you work for a company that wants to estimate whether a meeting room is occupied from its sensor readings. Your task is to compare the predicted occupancy with the recorded occupancy and choose a decision threshold. A false positive could keep the lights on in an empty room. A false negative could turn them off while people are still there.

We will use this example throughout the module.

Explore the occupancy notebook below. The sensor data is included, so you can run the example directly in the course.

The following marimo notebook contains 8,143 sensor readings and a slider for the decision threshold. A reading is predicted as occupied when its score is at least the threshold. These controls use the widgets introduced in [Module 3](/?module=3).

## 2. Use your notebook as a script or Python module

### Run the notebook as a script

You can run the occupancy notebook you explored above as a script from the command line. This is useful when you want to run the same analysis repeatedly without opening the notebook interface. For example, you might want to process a batch of sensor readings and save the results for a dashboard or report.

As you saw in Module 1, a notebook cell can have a Python function name. Here, `script_options` is the cell that reads the input file, threshold, and output filename. The updated cells use these values when the notebook runs as a script.

<MarimoEmbed
  notebook="/notebooks/module-5/occupancy.py?v=20261005-1"
  title="Add script support to the occupancy notebook"
/>

In the notebook, the `script_options` cell reads three command-line arguments:

- `--input` specifies the sensor data file. If you leave it out, the notebook uses `occupancy.csv`.
- `--threshold` specifies the threshold to use.
- `--output` specifies where to save the predictions.

The `selected_model` cell uses the threshold from the command line when the file runs as a script. The `save_predictions` cell writes the CSV and prints the summary. In the editor, the notebook continues to use the slider.

To try it in a terminal, run the command below from the folder containing `occupancy.py` and `occupancy.csv`:

```bash
uv run occupancy.py \
  --threshold 0.5 \
  --output occupancy_predictions.csv
```

You should see output similar to the following:

```text
Wrote 8143 rows to occupancy_predictions.csv
False positives: 90; false negatives: 5
```

### Reuse functions from the notebook

Another advantage of a marimo notebook is that it is a Python file. You can import its functions into another notebook instead of copying code.

You already explored the occupancy notebook above. Its `score_readings()` and `evaluate_occupancy()` functions are already in the correct format for reuse: each is defined in its own cell and uses imports from the setup cell. When your own function follows this pattern, marimo marks it as reusable in the editor.

When another notebook or Python program needs the same scoring rule, import the functions from `occupancy.py`:

```python
from occupancy import evaluate_occupancy, score_readings
```

The functions remain in one source notebook, so you can update the scoring rule in one place and use it wherever you need it.

## 3. Create views from one notebook with marimo Studio

App view and exports let you share a notebook as it is. Sometimes, however, different audiences need different ways to use the same analysis. Copying the notebook for each audience can create versions that drift apart. Adding all the presentation code to the notebook can also make the analysis harder to read.

With [marimo Studio](https://marimo.io/blog/introducing-marimo-studio), the analysis stays in one notebook while you create separate views on top of it.

<img src={studioNotebookViews} alt="Without Studio, separate notebook copies or presentation code inside one notebook serve each audience. With Studio, one notebook provides separate views for different audiences." />

<p className="figure-caption">
  marimo Studio keeps the analysis in one notebook and gives each audience a separate view. A change to the analysis can then be used by every view. Source: <a href="https://marimo.io/blog/introducing-marimo-studio">Introducing marimo-studio</a>.
</p>

For our occupancy analysis, the same notebook can be useful in three different ways:

- A **facilities team** might want a monitor showing the current occupancy results.
- Someone choosing the **decision threshold** might need a model review that makes false positives and false negatives easier to compare.
- A **manager** might want a short report summarising the results.

All three can use results from the same notebook which continues to contain the data and Python calculations. Each view chooses which results to show and how to arrange them.


### Create a simple view manually

Creating a Studio view is simple. In this activity, let's create a small view from the occupancy notebook.

<Callout title="Start marimo Studio locally">

To create Studio views locally, [download the notebook and data](/notebooks/module-5/module-5-occupancy.zip) and extract the `module-5-occupancy` folder. Open a terminal in that folder, which contains `occupancy.py` and `occupancy.csv`, then run:

```bash
cd module-5-occupancy
uvx --with marimo-studio marimo edit occupancy.py --sandbox --watch
```

Studio opens `occupancy.py` in your browser. Continue with the steps below.

</Callout>

With `occupancy.py` open, click the arrow beside the current view name in the top bar, then select **Add view**. Enter `simple-view` as the name, choose **HTML document**, and select **Create view**. If an existing view opens first, this adds `simple-view` alongside it.

<img src={studioAddSimpleView} alt="The Studio Add view panel with simple-view entered as the name and HTML document selected." />

Click the **Source** button (`<>`) in the Studio toolbar. In the source panel, open `index.html`, select all of its contents, and replace them with:

```html
<!doctype html>
<html>
  <head>
    <meta charset="utf-8" />
    <title>Occupancy results</title>
  </head>
  <body>
    <div id="app-shell">
      <main>
        <h1>Occupancy results</h1>
        <marimo-cell name="metrics_output"></marimo-cell>
      </main>
    </div>
  </body>
</html>
```

Save the file, then open **Preview**. The `<marimo-cell>` element tells Studio to render the output of the notebook cell named `metrics_output` inside the view.

<img src={studioSimpleView} alt="The occupancy notebook beside Studio Preview, which displays the metrics_output cell in a simple HTML view." />

<p className="figure-caption">
  The view references the notebook's <code>metrics_output</code> cell. The calculation remains in <code>occupancy.py</code>, while the view controls where the result appears.
</p>

You could continue building the view manually, as you just saw, or use an AI agent, as you will see in the next section.

### Create Studio views with marimo pair

Studio views can be created manually, as you just saw, or you can create them with an AI agent.

In [Module 4](/?module=4), you used [marimo pair](https://marimo.io/pair) to connect an AI agent to a running notebook. You will use it again here to create Studio views. marimo pair gives the agent access to the active notebook, so it can inspect the existing analysis, create Studio view files, and help you check the result.

With the local `occupancy.py` notebook open, select **Actions → Pair with an agent**, choose your AI agent, and follow the connection instructions.

<img className="lesson-gif" src={marimoPairGif} alt="The Actions menu in a local occupancy notebook shows the option to pair with an agent." />

If this is your first time using Pair, return to [Module 4](/?module=4) for the installation and setup steps, or read the [marimo pair guide](https://docs.marimo.io/guides/generate_with_ai/marimo_pair/). You can pair with Codex, Claude Code, Cursor, or another compatible AI agent.

### Create a monitor

First, send this prompt to your paired agent:

```text
Inspect occupancy.py.

Identify the notebook cells and values that contain:
- the threshold control
- precision and recall
- false positive and false negative counts
- prediction errors

List their names and briefly explain what each one contains.

Do not change any files yet.
```

AI agents may word their answers differently. In our run, the important parts were:

- `threshold_control` contains the threshold slider.
- `selected_model` calculates the predictions, metrics, and error rows.
- `metrics_output` displays precision, recall, false positives, and false negatives.
- `errors_output` displays the rows where the prediction is incorrect.

The underlying calculations remain in `score_readings()` and `evaluate_occupancy()`.

We can now build a view from these existing results instead of calculating them again. Send this prompt to your paired agent:

```text
Create a plain HTML Studio view named monitor for occupancy.py.

The view is for a facilities team. Show:
- the threshold control
- precision and recall
- false positive and false negative counts

Use the existing notebook cells and values. Keep all calculations in
occupancy.py. Keep the layout simple and easy to scan.

Build the view and show it in Preview.
```

The AI agent chooses the layout, so your monitor may look slightly different from the one shown below.

Change the threshold in the view and check that the values shown there match the notebook.

### Create a model review

The monitor gives a quick overview. Someone choosing the decision threshold needs more detail about how that threshold affects errors.

Send this prompt to your paired agent:

```text
Create another Studio view named model-review for occupancy.py.

This view is for someone choosing the occupancy decision threshold. Show:
- the notebook's threshold control
- precision and recall
- false positive and false negative counts
- a table of prediction errors

Add a short explanation of a false positive, predicting occupied when the
room is empty, and a false negative, predicting empty when the room is
occupied. Use the existing notebook results. Keep all calculations in
occupancy.py. Keep the view simple and focused on comparing errors.

Build the view and show it in Preview.
```

Set the threshold to `0.5`, then change it to `0.7`. Compare the precision, recall, false positive count, false negative count, and error rows at the two thresholds.

The monitor and model review use the same analysis, but they support different tasks. The monitor gives the facilities team a quick summary, while the model review makes the effect of the decision threshold easier to inspect.

### Create a report

Finally, create a view for someone who wants to read the results rather than explore them in detail.

Send this prompt to your paired agent:

```text
Create a Studio view named report for occupancy.py.

Make it a short report for a manager. Include:
- a short description of the occupancy task
- the selected threshold
- precision and recall
- false positive and false negative counts
- a short explanation of what the two errors mean in practice
- a short takeaway

Use the existing results from occupancy.py. Keep all calculations in the
notebook. Use a simple report layout with a title, summary metrics,
explanation, and conclusion. Build the view and show it in Preview.
```

<img src={occupancyReport} alt="A Studio report view showing the occupancy threshold, prediction metrics, error explanation, and summary." />

Studio keeps each view in its own folder beside the notebook. After you create the views in this section, the Files panel will look like this:

```text
__marimo__/
└── studio/
    └── occupancy
        ├── simple-view/
        ├── monitor/
        ├── model-review/
        └── report/
```

As you can see, the calculations have not been copied into the views. They remain in a single marimo notebook while each view presents those results for a different audience.
