An interactive notebook is a great place to begin an AI project because it lets you experiment and test ideas quickly. However, your requirements may change when you need to share your work withi others or integrate it into a larger production system.

marimo lets you move from a notebook to a script, web app, shareable artifact, or reusable Python module without rewriting your code and in this module, you will see exactly how to do this.

## 1. Build a sentiment classifier

Imagine you work for a company that wants to understand sentiment in customer feedback. In this exercise, you will use two open-weight LLMs to classify product reviews as positive, negative, or neutral using zero-shot classification. You will then compare how the models label the same reviews.

<img src={sentimentClassifierFlow} alt="Twelve product reviews go through one zero shot prompt to two Ollama models. Each model returns sentiment labels, and the results are compared." />

### Set up Ollama

This module uses `gemma3:1b` and `qwen3:1.7b` through Ollama. Both models run on your computer, so you do not need an API key. 

<details className="setup-details">
  <summary>Install Ollama and download the models</summary>

  1. Download and install [Ollama](https://ollama.com/download).
  2. Start the local server from the command line.

  ```bash
  ollama serve
  ```

  3. Open a second command line window and download the models.

  ```bash
  ollama pull gemma3:1b
  ollama pull qwen3:1.7b
  ```

</details>

These controls use the widgets introduced in [Module 3](/?module=3). The example uses only a few reviews to keep the notebook simple, but you can add more to the list.

Now that you have a working notebook, you can share it with others in several ways as described in the following sections.

## 2. Export and share the notebook in multiple formats

When you share a traditional notebook, interactive controls and plots may not work for the recipient. marimo provides several export options that preserve the notebook's results in a format that is easier to share, including static HTML, PDF, and interactive WebAssembly HTML. Each format has different advantages so you can choose an export format based on how someone will use the report:

- Static HTML opens in a browser and shows the outputs that were present when you exported it.
- PDF gives you a fixed document.
- Markdown saves the notebook content in a text format that you can use in documentation.
- WASM HTML runs the notebook in the browser, so supported controls remain interactive without a Python server.

After you run the classifier, you can either select the **download** button in the notebook editor or export from the command line. From the download menu, select **Download as HTML** to include the notebook code or **Download as HTML (exclude code)** to share the results without showing the code. You can also download a fixed PDF or continue working with the notebook as Markdown, `.ipynb`, notebook source, or a flat Python script.

<img src={exportNotebook} alt="Opening the notebook download menu and choosing an export format." />

To export from the command line, enter these commands from the folder that contains the notebook:

```bash
marimo export html sentiment_classifier.py -o sentiment_report.html
marimo export pdf sentiment_classifier.py -o sentiment_report.pdf
marimo export html-wasm sentiment_classifier.py -o sentiment_wasm --mode run
```

<Callout title="WASM and local models">
A WASM notebook runs in the browser, but this classifier still needs access to Ollama. Someone without Ollama cannot send new reviews to the local models. Use static HTML or PDF when you only need to share completed results.
</Callout>

## 3. Share the notebook as a web app

Sometimes, you only want to interact with a notebook without seeing its code. App view makes this possible. It is useful when sharing the end result with business stakeholders or others who do not need to edit the analysis.

you can open the notebook in app view by selecting the **preview** button in the bottom right corner of the notebook editor. App view hides the code and shows only the controls and results. You can use the grid editor if you want to arrange the outputs before sharing the app.


<img src={appView} alt="Opening the sentiment classifier in app view so its controls appear without the notebook code." />

You can also run the notebook as a web app from the command line. Enter this command from the folder that contains marimo notebook:

```bash
marimo run notebook.py
```

## 4. Run the notebook as a script

Script mode is useful when you need to run the classifier repeatedly, such as processing a daily batch of product reviews and saving the results for a dashboard or report.

The notebook below is a separate version of the classifier for script mode. It does not include the model fields, review input, or run button from the interactive notebook. Instead, it receives the model names and output filename as command-line arguments and writes the results to a CSV file.

<MarimoEmbed
  notebook="/notebooks/module-5/sentiment_classifier_script.py?v=20260926-1"
  title="Run the sentiment classifier as a script"
/>

To support script mode, the notebook uses a helper named `run_as_script()`. It reads three values from the command line:

- `--model-a` chooses the first model.
- `--model-b` chooses the second model.
- `--output` sets the name of the CSV file.

It then calls the same `compare_reviews()` function used by the notebook controls and saves the dataframe as a CSV file. The script prints a message that shows how many rows were written to the file.

<img src={sentimentClassifierScriptFlow} alt="Model names and an output filename are passed to the classifier, which saves the results as a CSV file." />

Enter this command in the command line from the folder that contains `sentiment_classifier_script.py`:

```bash
uv run sentiment_classifier_script.py -- \
  --model-a gemma3:1b \
  --model-b qwen3:1.7b \
  --output results.csv
```

3. Change `--output` to `second_run.csv` and run the command again. Confirm that both CSV files are in the folder.

## 5. Reuse the classifier in another notebook

Since a marimo notebook is a Python file, many of the standard Python features can be used with it. For example, you can import functions from one marimo notebook into another. This lets you reuse notebook code without copying it.

For instance, we can use the function from the sentiment classifier notebook in a second notebook that evaluates new reviews.

To make a function available for import from a marimo notebook:

- Define the function in its own cell.
- Add `@app.function` above the function definition.
- If the function needs a package or a fixed value, define it in the notebook's setup cell. This special cell runs before the other cells and makes shared imports and values available to reusable functions.
- The function can also call another function marked with `@app.function`.
- Keep the notebooks in the same folder, or make sure Python can otherwise find the notebook being imported.

The sentiment classifier notebook follows these requirements for `compare_reviews()`. In the following notebook, a normal Python import brings that function into a new analysis and applies it to three new reviews. The notebooks are in the same folder, so Python can find the sentiment classifier. See the [marimo guide to reusing functions and classes](https://docs.marimo.io/guides/reusing_functions/) for more details.
